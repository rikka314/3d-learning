# Zero123++、Era3D 与 MV-Adapter 复现使用指南

## 研究问题与结论

本次研究回答的问题是：本地的 Zero123++、Era3D 和 MV-Adapter 复现是否已经可以使用，以及应如何把自己的单张图片送入三套模型。

结论如下：

- 当前机器上三套项目的本地虚拟环境均存在，Zero123++、Era3D standard 和 MV-Adapter i2mv 所需权重也已存在，可以直接运行，不需要重新安装。
- 三套复现当前完成的是“单张图像 → 多视图图像”，不是“单张图像 → 3D 网格”。输出不能直接当作 `.glb`、`.obj` 或可信医学几何。
- Zero123++ 适合作为快速 RGB 六视图基线。
- Era3D 同时输出 6 张 RGB 和 6 张 normal，是当前更适合连接后续几何重建的路线。
- MV-Adapter 当前只完成了 SD2.1 的 `i2mv`。需要已有 mesh 的 `ig2mv` 尚未运行，因为本机 WSL 没有满足要求的 CUDA toolkit / `nvcc` 与 `nvdiffrast` 环境。

## 使用前的统一输入准备

为了让三套模型的结果可以横向比较，应从同一张原始图制作各项目自己的输入副本，并保持主体尺度、方向和 seed 可记录。

建议输入满足以下条件：

1. 画面中只有一个主体，主体居中，周围留有少量边距。
2. 去除文字、水印、标尺、投影阴影和杂乱背景。
3. Zero123++ 使用方形 RGB 或 RGBA 图，建议不低于 320×320。
4. Era3D 必须使用带有非空 alpha 前景的 RGBA PNG/WebP。
5. MV-Adapter 当前包装脚本不会自动去背景；使用已去背景的 RGBA PNG 最稳妥。
6. 对医学资产保留来源、许可证、尺度语义和审核状态。生成视图只能视为模型推断，不能视为患者特异或解剖真值。

## Zero123++：快速 RGB 六视图

将输入放入：

`reproductions/多视图复现/zero123/inputs/`

然后在 Windows PowerShell 中运行：

~~~powershell
cd "D:\Learn\20_Projects\3dresearch\3d-learning\reproductions\多视图复现\zero123"

.\run.ps1 `
  -Input ".\inputs\organ.png" `
  -Steps 28 `
  -Seed 42 `
  -Offline
~~~

默认输出为：

~~~text
outputs/organ_s42_n28.png
~~~

它是一张包含六个固定视角的网格图，不是六个独立文件，也不是 3D 网格。若显存紧张，可以增加 `-CpuOffload`，代价是运行更慢。

固定相机约定为：

- 相对方位角：30、90、150、210、270、330 度。
- 绝对仰角：20、-10、20、-10、20、-10 度。
- 统一视场角：30 度。

## Era3D：RGB 与 normal 批量生成

把一张或多张已去背景 RGBA 图片放入：

`reproductions/多视图复现/era3d/inputs/`

然后运行 standard：

~~~powershell
cd "D:\Learn\20_Projects\3dresearch\3d-learning\reproductions\多视图复现\era3d"

.\scripts\run.ps1 `
  -Variant standard `
  -Seed 600 `
  -CropSize 420 `
  -DataloaderWorkers 0
~~~

每次运行会创建新的时间戳目录：

~~~text
outputs/<timestamp>-standard-seed600/<case>/
├── color_*.png
└── normals_*.png
~~~

每个 case 预期包含 6 张 RGB 和 6 张 normal。脚本会处理 `inputs/` 中的所有 PNG/WebP；当前目录内保留了官方 demo，因此只想处理自己的案例时，应先把 demo 移到输入目录之外。

对正面取向明确、透视畸变很小的教学渲染，可以选择正交模型：

~~~powershell
.\scripts\download_weights.ps1 -Variant ortho
.\scripts\run.ps1 -Variant ortho -Seed 600 -CropSize 420
~~~

`DataloaderWorkers` 应继续保持为 0。当前项目路径较长，设置为 1 曾触发 WSL AF_UNIX socket 路径过长错误。

## MV-Adapter：prompt 条件的 i2mv

将输入放入：

`reproductions/多视图复现/mv-adapter/inputs/`

运行：

~~~powershell
cd "D:\Learn\20_Projects\3dresearch\3d-learning\reproductions\多视图复现\mv-adapter"

.\scripts\run.ps1 `
  -Mode i2mv `
  -Image "inputs/organ.png" `
  -Output "outputs/organ-sd21.png" `
  -Prompt "high quality anatomical teaching model of a human heart" `
  -Steps 50 `
  -Seed 0
~~~

`-Image` 与 `-Output` 应使用 MV-Adapter 项目根目录下的相对路径。输出包括：

~~~text
outputs/organ-sd21.png
outputs/organ-sd21_reference.png
~~~

第一张是 3072×512 的横向六视图网格，每个视图为 512×512；第二张是实际送入 pipeline 的参考图。prompt 主要控制语义、风格和材质描述，不能代替几何约束。

目前不要把以下命令视为已经可用：

~~~powershell
.\scripts\run.ps1 -Mode ig2mv -Image inputs/organ.png -Mesh inputs/organ.glb
~~~

该路线仍需要 CUDA toolkit、`nvcc`、`nvdiffrast` 和 geometry 依赖的安装与端到端验证。

## 选择建议

| 目标 | 推荐路线 | 原因 |
| --- | --- | --- |
| 快速确认单图能否形成合理六视图 | Zero123++ | 推理快、接口简单、显存压力相对小 |
| 为后续重建准备 RGB 与法线线索 | Era3D standard | 已输出独立 RGB/normal，多视图几何信息更完整 |
| 需要 prompt 控制外观或语义 | MV-Adapter i2mv | 支持文本条件，输出六个 512×512 视图 |
| 使用可信 mesh 约束相机与几何 | MV-Adapter ig2mv | 目标路线合适，但当前本地实现尚未完成 |

三套模型应串行运行。MV-Adapter 在 RTX 5070 12GB 上的本地记录显示 50 步运行峰值约 10GB 显存，不建议同时启动其他 GPU-heavy 任务。

- 生成结果的解剖结构真实性仍需用真值视角、可信 mesh 或专家审核验证。

如果下一阶段目标是得到真正的 3D 模型，合理顺序是：

1. 为同一医学对象准备经过审核的 RGBA 输入。
2. 分别运行三套多视图生成，并记录 seed、耗时、显存和相机顺序。
3. 将输出拆成统一的单视图格式。
4. 接入同一重建器，避免因为不同下游重建算法而污染模型比较。
5. 用轮廓、解剖标志点、法线和留出真值视角做评估。
