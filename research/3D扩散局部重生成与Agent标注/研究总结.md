# 3D 扩散局部重生成与 Coding Agent 标注研究

> 归档日期：2026-09-02  
> 研究性质：能力边界与工程路线判断  
> 当前状态：完成概念调研和本地能力核查，尚未实现或验证局部重生成原型

## 原始问题与研究目标

本次研究围绕三个连续问题展开：

1. Coding agent 能否直接修改 3D diffusion 产出的模型？
2. 能否先选定 3D 模型的一部分，再让 3D diffusion 只重新生成这一部分？
3. Coding agent 能否完成上述选区的标注工作？

这里默认“3D diffusion 产出的模型”指生成出来的 3D asset，而不是 diffusion 神经网络本身。两者必须区分：前者是 mesh、point cloud、3D Gaussian、NeRF 等可视资产；后者是模型架构、latent 和训练权重。

研究目标不是选定某一个生成模型，而是判断这些能力是否成立、成立所需的表示和接口，以及当前项目可以采用的最小工程路径。

## 核心结论

### 1. Coding agent 可以修改生成资产，但受 3D 表示约束

这是一个**有条件成立的能力判断**。

- 对 `.obj`、`.fbx`、`.glb` 等显式 mesh，agent 可以通过 Blender Python 修改顶点、面、对象层级、材质、UV，执行 Boolean、remesh、平滑和导出。这类操作不需要再次使用 diffusion。
- 对 point cloud，agent 可以删除、移动、标记或替换点，但生成结果如需成为可渲染曲面，通常还需要 surface reconstruction 或后续 meshing。
- 对 3D Gaussian Splatting，可以选择和冻结一部分 Gaussian，并对局部参数重新优化；它不是普通 mesh 编辑。
- 对 NeRF 或其他 implicit field，一般需要专门的神经场编辑流程，或者先提取 mesh 再处理。
- 对 diffusion latent 或模型权重，coding agent 可以修改代码、配置并执行训练或优化，但不能把某个权重直接解释为“椅子腿长度”并进行确定性手工修改。

因此，coding agent 的作用应理解为：**操作资产和工具、编排生成模型、执行拼接与验证**，而不是自身取代 3D diffusion。

### 2. 只重新生成选定区域在技术上可行，但不是普通 3D diffusion 的默认能力

这是一个由多项研究工作支持的**已验证可行方向**：

- ShapeFusion 把局部编辑表述为 mesh 上的 masked diffusion。用户可以定义任意顶点区域，对选区加噪和去噪，同时保持未选区域不变。其重要限制是采用固定 mesh topology，实验重点是人脸和人体，并不能直接推广为“任意生成 GLB 的通用局部编辑器”。
- Blended Point Cloud Diffusion 将局部编辑表述为 point-cloud inpainting：输入二值 mask，使用未编辑部分作为结构条件，只生成目标区域，并通过坐标 blending 改善身份保持。
- SALAD 使用 part-level implicit representation，使 diffusion 可以完成部件补全、混合和操作；这说明表示中具有结构信息时，局部控制更自然。
- PartGen 从文本、图像或未结构化 3D 对象中生成有意义的独立部件，并展示了 part editing；它适合作为“先分件，再独立编辑”的参考路线。

上述证据支持的准确结论是：

> 局部重生成需要模型或工作流显式支持 mask、partial shape、part latent 或固定拓扑约束。普通的全局 text-to-3D / image-to-3D 推理接口通常不能仅靠传入一组顶点就保证其他区域完全不变。

### 3. Coding agent 可以完成标注，但标注方式影响可靠性

标注可以分为三档：

1. **用户选择、agent 持久化**：最可靠。用户在 Blender 中选中 faces、vertices 或 object，agent 将其保存为 vertex group、独立 object、face attribute 或外部 JSON mask。
2. **几何规则自动标注**：较可靠。agent 可以根据坐标范围、bounding box、连通分量、材质、法线或与 seed face 的拓扑距离自动选择区域。
3. **语义自动标注**：可实现但需要额外感知模型。识别“椅子左前腿”通常需要多视图渲染、2D segmentation、跨视图一致性和 mask-to-mesh 反投影；边界结果仍应由人确认。

对于医学教育资产，语义标签还应绑定 canonical anatomy ID，并检查数量、左右侧、连接关系和关键地标，不能只依赖视觉相似度。

## 本地项目的已验证状态

当前仓库已经固定复现 Blender-MCP。根据 [Blender-MCP README](../../reproductions/agent-3dgeneration/Blender-MCP/README.md)，它是一座 MCP client 到 Blender addon 的桥，能够让 Blender 在主线程中执行 `bpy` 操作。这为 agent 读取选择、写入标注、修改 mesh 和导出结果提供了技术入口。

但必须保留以下状态边界：

- Python 包、MCP stdio、Blender addon 安装和后台加载基线已验证。
- Blender GUI 中启动 addon server、MCP TCP 握手、真实场景编辑和 `.blend/.glb` 输出尚未完成端到端验证。
- 具体边界见 [Blender-MCP AI_CONTEXT](../../reproductions/agent-3dgeneration/Blender-MCP/AI_CONTEXT.md)。

因此，当前可以确认的是“本地已有合适的控制桥”，不能声称“coding agent 的局部标注和生成闭环已经跑通”。

## 推荐的工程架构

当前更实际的路线是把交互、生成和几何处理分开：

```text
用户在 Blender 中选择区域
        ↓
Coding agent 保存 face/vertex/part mask
        ↓
局部 3D diffusion 或独立 part generator 生成候选
        ↓
Coding agent 对齐、拼接、平滑、修复纹理
        ↓
几何与语义验证后导出
```

建议标注记录至少包含：

```text
asset_id
part_name / semantic_id
face_indices / vertex_indices / point_indices
soft_mask_weights
boundary_ring
locked_region
edit_prompt
reference_images
seed_and_model_version
```

其中 `boundary_ring` 应作为独立约束保存。局部生成最大的工程风险往往不是选区内部质量，而是新旧区域之间的 topology、法线、曲率、UV 和纹理接缝。

## 两条可选实现路线

### 路线 A：原生 masked 3D diffusion

直接在 mesh 或 point-cloud 表示上固定未编辑区域，只对 mask 内执行 forward noise 和 reverse denoising。

优点：局部性定义清晰，理论上可以严格保持未编辑区域。  
限制：通常要求特定拓扑、训练数据和模型结构，难以直接接入任意现成 text/image-to-3D 模型。

### 路线 B：分件生成后在 Blender 中替换

先把目标区域切分为独立 part，保留接口边界和锚点；使用 image/text-to-3D 生成替换件；最后由 agent 在 Blender 中完成尺度、姿态、边界和材质融合。

优点：更容易复用现有完整物体生成模型和 Blender 工具链。  
限制：新部件与原模型的接缝、风格和拓扑一致性需要额外修复。

**当前建议**：先实现路线 B 的最小闭环，以验证标注协议、模型调用和拼接流程；只有当“未选区域严格不变”成为核心指标时，再投入原生 masked diffusion。该建议尚未被实现，也不是已经作出的项目决策。

## 建议的最小验证原型

选择一个拓扑简单、语义明确的资产，例如四条腿的椅子：

1. 在 Blender 中手动选择一条椅子腿。
2. 由 agent 将选择保存为 vertex group 和 JSON face-index mask。
3. 提取该部件以及一圈连接边界，记录局部坐标系和锚点。
4. 先不接 diffusion，使用一个确定性替换件验证切分、对齐、缝合和导出。
5. 再接入 part generator 或 point-cloud inpainting 模型。
6. 比较编辑前后未选区域的顶点坐标哈希，验证其是否真正保持不变。
7. 检查 non-manifold edges、自相交、法线、UV、纹理接缝和部件穿插。

这个顺序能够先隔离 Blender/标注/拼接问题，避免把所有失败都归因于生成模型。

## 风险、假设与未完成事项

- 本次没有指定具体 3D diffusion 产品或仓库，因此不能判断某一现成 API 是否支持 mask 输入。
- “选中一部分”可能指 mesh faces、语义部件、3D bounding volume 或多视图 2D mask；不同输入需要不同的 mask 投影和持久化方式。
- ShapeFusion 等工作证明了局部生成的可行性，但其数据域和拓扑约束较强。
- 语义自动标注不是纯 coding 问题，需要视觉或 3D segmentation 模型；生成资产若本身已经分件，难度会显著下降。
- 当前本地 Blender-MCP 还缺真实 GUI 端到端验证。
- 本次没有修改生成、标注或 Blender 源代码，也没有运行任何 diffusion 推理。

后续最有价值的工作是：明确候选 3D diffusion 的输入输出表示与许可，然后用一个椅子资产实现“手选区域 → 持久化 mask → 确定性替换 → 导出验证”的最小闭环。
