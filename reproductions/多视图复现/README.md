# 多视图复现

本目录用于在同一硬件和输入约定下复现三条单图多视图生成路线，并为后续 3D 重建提供一致输入：

| 项目 | 角色 | 首轮目标 | 目录 |
|---|---|---|---|
| Zero123++ | 轻量 RGB 多视图基线 | 已通过：28 步生成 6 个固定视角 | [`zero123/`](./zero123/) |
| Era3D | RGB + normal 几何基线 | 已通过：40 步生成 6 RGB + 6 normal | [`era3d/`](./era3d/) |
| MV-Adapter | 几何条件主线 | 已通过：SD2.1 i2mv 50 步生成 6 视图 | [`mv-adapter/`](./mv-adapter/) |

## 统一范围

- 本轮只验证“单图 → 一组相机一致的多视图”；3D 网格重建作为下一阶段接入，不把多视图图片误称为 3D 模型。
- 首先用各上游官方示例建立可运行基线，再换成医学输入。
- 医学方向依次覆盖：标准化教学器官、单细胞细胞核、细胞器空间结构。
- 教学器官可以采用 `verified geometry → 标准视角渲染 → 多视图生成`；细胞结构必须记录图像来源、尺度语义与可见结构，不能把纹理幻觉当成可信结构。
- 所有源码、环境、权重缓存、输入、输出和日志都保存在本目录的对应项目子目录中。
- 三套模型共用且不可变的医学原始资料保存在 [`medical-assets/`](./medical-assets/)；模型实际输入和派生结果仍进入各项目目录。

## 完成门槛

| 阶段 | 判定标准 |
|---|---|
| A. 固化源码 | 官方仓库已拉取，README 记录 commit 与许可证 |
| B. 环境冒烟 | 隔离环境可创建，核心包可以 import，CUDA 架构与 GPU 可见性有日志 |
| C. 官方样例 | 官方输入成功生成预期数量/类型的视图，保存命令、日志与输出 |
| D. 医学样例 | 三类输入各至少 1 个，使用相同预处理、相机约定和随机种子 |
| E. 3D 接入 | 多视图进入同一重建器，记录网格、纹理、失败模式和可验证结构约束 |

当前三条路线的 A–C 均已完成。D 已建立统一案例、来源和评估协议并下载 Z-Anatomy 原始资产，但尚未完成三类医学输入的正式推理；E 尚未开始。

## 本机基线

- Windows + WSL2 Ubuntu 24.04
- NVIDIA GeForce RTX 5070，12GB VRAM
- D 盘可用空间：执行前约 254GB
- 主机无 Conda；优先使用 WSL 内项目本地 `.venv`
- RTX 50 系列需要支持 Blackwell（`sm_120`）的 PyTorch/CUDA 组合；若上游锁定旧版 PyTorch，项目 README 必须明确记录兼容偏差

## 统一输出纪律

每个项目目录都使用以下本地目录，且不提交大文件：

```text
cache/       # Hugging Face、Torch 等缓存
checkpoints/ # 手工或脚本下载的权重
inputs/      # 原图及来源说明
logs/        # 环境检查与运行日志
outputs/     # 生成结果
upstream/    # 固定版本的官方源码
.venv/       # 项目隔离环境
```

医学样例、真值与指标定义见 [`MEDICAL_BENCHMARK.md`](./MEDICAL_BENCHMARK.md)。

最终比较时至少记录：峰值显存、耗时、输出视图数、RGB/normal 类型、相机顺序、跨视图结构一致性，以及对关键解剖结构的人工核对结果。
