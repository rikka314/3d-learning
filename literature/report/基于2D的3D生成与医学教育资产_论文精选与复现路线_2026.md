# 基于 2D 的 3D 生成与医学教育资产：论文精选与复现路线

> 生成日期：2026-08-25  
> 当前主线：`image → 3D` 与 `image + text → 3D`  
> 长期低优先级：coding agent 直接生成 Three.js / parametric 3D 代码  
> 产品边界：面向教育展示，不用于诊断、治疗、手术规划或患者特异性结论  
> 调研口径：优先论文原文、CVF/OpenReview、官方代码、官方数据集与许可证；2026 年最新工作单独核验  
> 综合置信度：高（路线选择与开源可复现性）；中（模型在医学插图域的相对优劣，仍需本项目实测）

## 结论先行

项目现在不应继续平均铺开 52 篇 3D AI 论文。近期只保留两条紧密相连的研究路径：

1. **`image → 3D`：**先把单图到可加载 GLB/PBR mesh 的工程链跑通并做统一评测。
2. **`image + text → 3D`：**验证文字能否补充器官类别、结构名称、观察方向、允许的简化和风格要求，而不是假定文字能恢复图中不存在的真实几何。

医学教育资产应采用一个更严格的双层策略：

- **可发布层：`verified geometry + generative presentation`。**核心几何来自许可清晰、可追溯的 canonical anatomy mesh 或 scan-derived segmentation；2D/text 用于材质、颜色、风格、标签、分层和镜头表达。
- **实验层：`2D/text → generated geometry`。**允许生成几何作为草模，但必须与 canonical mesh、关键地标和 part graph 比较，经专家审核后才可进入教育内容。

这不是把 2D 主线改回传统医学影像工程，而是明确：**2D 仍是创作入口，但不能成为不可见解剖结构的唯一事实来源。**2026 年一项面向医学教育图像的同行评审研究中，表现最好的 text-to-image 模型在“结构存在且生理正确”联合标准下也只有 37.4% 的结构项完全正确，因此视觉可信不能替代解剖审核。[Strugała et al., 2026](https://pubmed.ncbi.nlm.nih.gov/42478089/)

### 现有精选的主要问题

- 当前 `精选/` 把单资产、场景、4D、世界模型和医学方向混在一起；对本项目近期目标过宽。
- 现有医学报告偏 CT/MRI、临床重建和患者特异性模型；它对安全边界有价值，但不是当前教育资产生产路线本身。
- `reproductions/` 仍为空，说明项目尚未建立“同输入、同输出、同指标”的模型比较基线。
- 当前资料缺少几篇真正决定 image-to-3D 技术演化和可复现性的关键论文：Zero-1-to-3、LRM、InstantMesh、SPAR3D、Hunyuan3D 2.1、Hi3DGen、Dehallu3D、Hi3DEval 与 Fuse3D。

## 二、分四期阅读

目标不是把每篇从头到尾平均精读，而是每期解决一个决策问题。共 4 期，约 5–7 周。

### 第一期：理解 2D 为什么能抬升为 3D，以及为什么会错

**目标：**建立 `2D prior → novel views → reconstruction → 3D-native latent` 的技术地图。预计 7–10 天。

| 顺序 | 论文 | 重点阅读 | 是否复现 |
|---:|---|---|---|
| 1 | [DreamFusion](../papers/3D生成与3D_AI最新进展_2026/R08_DreamFusion.pdf) | SDS、camera sampling、Janus、多视图语义重复、逐样本优化成本 | 否 |
| 2 | [Zero-1-to-3, ICCV 2023](https://openaccess.thecvf.com/content/ICCV2023/html/Liu_Zero-1-to-3_Zero-shot_One_Image_to_3D_Object_ICCV_2023_paper.html) | 单图 novel-view diffusion、视角条件、不可见面为何只是 prior | 否 |
| 3 | [LRM, ICLR 2024](https://openreview.net/forum?id=sllU8vvsFF) | 500M Transformer、单图前馈 NeRF、约百万对象训练如何改变范式 | 否 |
| 4 | [InstantMesh](https://arxiv.org/abs/2404.07191) / [official code](https://github.com/TencentARC/InstantMesh) | multi-view diffusion 与 sparse-view LRM/FlexiCubes 的分工 | 只跑 3–5 个 demo |
| 5 | [TRELLIS, CVPR 2025](https://openaccess.thecvf.com/content/CVPR2025/html/Xiang_Structured_3D_Latents_for_Scalable_and_Versatile_3D_Generation_CVPR_2025_paper.html) | SLAT、稀疏结构、同一 latent 解码 mesh/3DGS/radiance field | 可跑 inference，不训练 |

**读完必须能回答：**哪些几何来自输入证据，哪些来自生成 prior；为何多视图一致不等于隐藏结构正确；为何 2025 年后主流从逐样本 SDS 转向前馈 LRM 与 3D-native latent。

### 第二期：建立可交付的 image-to-3D 工程基线

**目标：**比较 direct GLB、PBR、背面补全、拓扑和显存成本。预计 10–14 天。

| 优先级 | 论文 / 项目 | 关键价值 | 开源与算力 | 动作 |
|---|---|---|---|---|
| A | [SPAR3D, CVPR 2025](https://arxiv.org/abs/2501.04689) / [official code](https://github.com/Stability-AI/stable-point-aware-3d) | 单图先生成可编辑 point cloud，再生成 textured mesh；便于修正背面 | 默认约 10.5GB，low-VRAM 约 7GB；直接 GLB；Windows/MPS 为实验支持 | **首个复现** |
| A | [Hunyuan3D 2.1](https://arxiv.org/abs/2506.15442) / [official code](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1) | shape/texture 两阶段、PBR、训练与推理代码开放 | shape 约 10GB、texture 约 21GB、完整约 29GB；需单独审计社区许可 | **主生产候选复现** |
| A | [Native and Compact Structured Latents / TRELLIS.2, CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Xiang_Native_and_Compact_Structured_Latents_for_3D_Generation_CVPR_2026_paper.html) / [official code](https://github.com/microsoft/TRELLIS.2) | O-Voxel 可表达 open/non-manifold/内部封闭表面和 PBR 属性 | Linux + NVIDIA ≥24GB；MIT 代码；官方 H100 速度不可直接外推到消费卡 | **高端上界复现** |
| B | [TripoSG](https://arxiv.org/abs/2502.06608) / [official code](https://github.com/VAST-AI-Research/TripoSG) | SDF mesh、约 8GB 门槛、MIT；适合线稿/规范插图对照 | ≥8GB CUDA；直接 GLB | 显存或许可受限时优先加入 |
| B | [Hi3DGen, ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/html/Ye_Hi3DGen_High-fidelity_3D_Geometry_Generation_from_Images_via_Normal_Bridging_ICCV_2025_paper.html) / [official code](https://github.com/bytedance/Hi3DGen) | 以 normal bridging 提升细节几何；适合观察器官沟回、骨性地标 | 代码 MIT；主要强化 geometry，需另配纹理管线 | 精读，暂不进首轮四模型 |
| B | [AssetGen, 2026](https://arxiv.org/abs/2605.26137) | UV、简化、normal baking、polygon budget、pipeline latency | 论文系统完整，但复现资源开放度不如前三者 | 精读 production pipeline |

## 三、明确要复现哪几个

### 立即复现：3 个主项目

#### R1. SPAR3D：低成本 image-to-3D 基线

**原因：**7GB 左右 low-VRAM、直接输出 GLB、point cloud 中间表示可编辑，最适合先把 benchmark、资产保存和 Three.js 加载链跑通。

**复现完成标准：**

- 官方 inference 能在固定环境、固定 seed 下批处理；
- 保存输入、point cloud、中间 mesh、最终 GLB、六视图 render、耗时与显存；
- GLB 通过 validator 并可在 Three.js 中加载；
- 对简单器官/骨骼输出建立第一版几何与教育审核表。

#### R2. Hunyuan3D 2.1：PBR/可交付资产主候选

**原因：**shape 与 PBR paint 分离，能把“几何是否正确”和“外观是否好看”拆开评估；公开训练/推理代码，适合后续 domain adaptation。

**复现完成标准：**

- 分别跑 shape-only、paint-only、end-to-end；
- 检查 albedo、roughness、metallic，而不是只看最终灯光渲染；
- 输出统一 GLB/LOD，记录 10GB/21GB/29GB 三种阶段的实测资源；
- 完成官方许可证、模型权重条款和目标发布地区审计。

#### R3. TIGON：image + text 研究主候选

**原因：**这是当前最直接回答第二条主线的正式论文和公开 inference。

**复现完成标准：**

- 对同一输入分别运行 `image-only`、`text-only`、`image+text`；
- prompt 固定为结构化字段：对象、视角、主要结构、左右侧、允许简化、禁止新增结构、展示风格；
- 评估文字是否改善条件遵循，还是引入新的隐藏结构幻觉；
- 由于当前发布主要输出 Gaussian，先验证条件融合，不把它强行当 production GLB winner。

### 有 24GB+ Linux GPU 时追加：TRELLIS.2

TRELLIS.2 是 image-to-PBR-GLB 的高端上界，也最适合测试开放表面、非流形、内部封闭结构；但 4B 模型和稀疏 CUDA 依赖使它不适合做第一个环境。完成 SPAR3D benchmark 后再接入，能避免把时间浪费在基础设施而没有可比较结果。

### 条件性追加

- **TripoSG：**8GB 左右、MIT、直接 GLB。显存有限或目标产品无法接受 Stability/Tencent 社区许可证时，应列入首轮。
- **Fuse3D：**当单图背面/局部结构失败率高，且能提供多张审核过的 2D 参考时复现。
- **PartGen：**当产品明确需要可独立隐藏、着色、点击的器官部件时复现；它会补全甚至幻觉不可见部件，必须使用医学 part ontology 重新验收。
- **InstantMesh：**作为教学性方法链和旧基线保留，不与 2025–2026 的主生产模型平均投入。

### 不复现

- DreamFusion：历史价值高，工程价值低。
- 训练新的 TRELLIS/Hunyuan/TIGON foundation model：近期数据与算力投入不合理。
- 4D/world-model/scene generation：与当前单资产教育产品不在同一优先级。
- MAISI/3D MedDiffusion：生成的是医学 volume，除非以后明确要做 scan-derived shape prior，否则不进入当前复现队列。

## 四、统一 benchmark：不要各跑各的 demo

### 第一批对象

从 BodyParts3D 或另一许可明确的 canonical atlas 中选 6 个对象：

- 简单外形：肾、股骨；
- 中等复杂：肝、胃；
- 高曲面复杂度：脑、心脏外表面。

首轮不选血管树、神经丛、复杂心脏切面和病灶。这些对象的连通性与内部关系太敏感，应在基础模型筛完后单独建立难集。

### 输入条件

每个对象至少准备：

1. canonical mesh 的单张标准 2D render；
2. 同一 mesh 的 4–6 张审核过的多视图 render；
3. 与单图配套的结构化 text；
4. 可选的 textbook-style 彩色插图，用来测 domain shift。

### 保存内容

- 来源、许可证、hash、模型版本、checkpoint、seed、prompt；
- 原始输出与所有后处理版本，禁止只保留“最好看”的成品；
- 六视图 render、normal/depth、triangle count、texture size、生成时延和显存峰值；
- GLB validator 结果、Three.js 加载结果与 LOD；
- reviewer 结论和失败原因。

### 四层评测

1. **条件/外观：**多视图轮廓、颜色/材质、text 条件遵循；
2. **几何：**ICP 对齐后 Chamfer/NSD/HD95、关键地标、体积与局部表面误差；
3. **结构：**部件数、左右侧、连接/包含关系、孔洞、突刺、自交、non-manifold、漂浮组件；
4. **工程：**GLB 有效性、UV/PBR、三角面数、文件大小、Three.js 加载和移动端 LOD。

医学 reviewer 使用三档：

- `可教学使用`：关键结构与关系正确，只存在可接受的网格/纹理简化；
- `仅概念展示`：大体形态可用，但细节或隐藏面不可靠，必须显式标注；
- `不可使用`：缺失/新增结构、左右颠倒、错误连接、严重比例或拓扑错误。

## 五、医学教育资产的推荐生产架构

```text
可信 canonical anatomy mesh / scan-derived segmentation
        │
        ├─ render 2D RGB / normal / depth / part-ID / multi-view references
        │
        ├─ image-to-3D / image+text-to-3D 生成候选草模
        │
        └─ shape-conditioned texturing 直接为可信 mesh 生成外观
                    ↓
canonical alignment + landmark / part-graph / topology QC
                    ↓
人工修订与医学 reviewer 审核
                    ↓
GLB + LOD + labels + provenance + “教育用途/非诊断”元数据
                    ↓
Three.js viewer
```

### 两类发布等级

| 等级 | 几何来源 | 允许用途 |
|---|---|---|
| Verified educational asset | canonical mesh 或由公开 scan segmentation 导出；生成模型只做受约束修饰 | 正式课程、互动教学、标签与测验 |
| Approximate generated asset | image/text-to-3D 生成后通过基础 QC，但没有完整医学真值 | 概念演示、低风险科普背景；必须显示 approximate 标识 |

**允许粗糙的内容：**网格密度、纹理细节、颜色风格、轻微表面平滑。  
**不允许粗糙的内容：**结构数目、左右侧、连接关系、包含关系、关键孔/管道/腔室、主要地标和比例。

## 六、长期低优先级：coding agent 直接生成 Three.js

这条线暂不占用近期复现资源，只保留一个季度观察位。

### 后续阅读

- [P3D-Bench, 2026](https://arxiv.org/abs/2606.11152)：评测 text/image/assembly 到 parametric 3D program 的可执行性、几何、拓扑和部件结构；结果表明 assembly 与精确参数仍是弱项。
- [CADCrafter, CVPR 2025](https://openaccess.thecvf.com/content/CVPR2025/html/Chen_CADCrafter_Generating_Computer-Aided_Design_Models_from_Unconstrained_Images_CVPR_2025_paper.html)：`image → CAD program`，用 compiler 检查 decoded commands，可借鉴“生成代码—执行—验证—重采样”闭环。
- [From Visual Synthesis to Interactive Worlds, 2026](https://arxiv.org/abs/2604.23629)：production-ready asset 全生命周期综述。
- [img2threejs](https://github.com/img2threejs/img2threejs)：2026 年的开源工程项目，不是同行评审论文；适合观察 image → structured spec → Three.js code → render review 的可编辑资产路线。

### 何时启动

只有满足以下两个条件才进入实现：

1. GLB/PBR 主线已经有稳定 benchmark、viewer 和 QA；
2. 产品明确需要 semantic parts、可编辑参数或程序动画，而不是普通 mesh 已能满足。

首个 coding-agent 实验应选硬表面、由 primitive 组成的教具或器械，不选器官、血管或神经。程序化 primitive 对有机解剖曲面并不占优势。

## 主要来源与方法

本次调研先盘点仓库 52 篇本地论文、25 张精选阅读卡、3 份现有报告和空的复现目录，再围绕以下四个问题检索并深读一手来源：

1. 2023–2026 年 image-to-3D 的技术转折；
2. 可直接复现的 GLB/PBR 开源系统与硬件门槛；
3. image+text、多图、部件化和去幻觉；
4. 医学教育资产的 canonical data、几何评测和专家审核边界。

纳入来源超过 30 个，核心结论以 CVF、OpenReview、arXiv 原文、官方 GitHub、BodyParts3D/NLM 等官方数据页和 PubMed 论文交叉核验。不同论文的作者自报指标、硬件、数据和 renderer 不可直接横向排名，因此本报告只给出复现顺序，不构造虚假的统一 SOTA 排名。
