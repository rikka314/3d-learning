## 执行摘要

截至 2026 年 8 月，3D AI 已经越过“从文本生成一个可旋转的物体”这一早期目标，进入三个同时发生的阶段转换。

第一，**单资产生成正在从 2D diffusion 蒸馏转向大规模 3D-native latent、flow matching 与结构化 token**。DreamFusion 时代的 Score Distillation Sampling（SDS）证明了 2D 生成先验可以监督 3D，但其逐样本优化慢、几何不稳定、容易产生 Janus/多面脸。2025 年的 TRELLIS、Hunyuan3D 2.x、TripoSG、Step1X-3D 等工作把生成改造成一次前馈或少步采样；2026 年的 O-Voxel、LATTICE、Omni123 又把问题进一步推进到“怎样用紧凑而原生的 3D latent 同时表达复杂拓扑、几何和材质”。〔R08, R10–R13, R17–R21〕

第二，**“看起来像 3D”不再是唯一目标，研究开始围绕 production-ready asset 重构任务定义**。PBR 材质、UV、受控面数、部件、关节、骨骼、蒙皮、参数化 CAD、物理材料与仿真可用性已成为独立研究对象。AssetGen 2026 能在 H100 上约 30 秒输出带 UV、烘焙法线和受控 polygon budget 的 textured mesh，Flash 版本约 14 秒；但论文同时承认 marching cubes 网格仍不保证 artist-friendly topology，也不天然满足 rigging/animation。这个“速度已接近交互、结构仍不够可交付”的反差，是当前最重要的现实判断。〔R02, R09, R14–R16, R20, R26–R28〕

第三，**单物体生成正在与场景生成、视频生成、几何重建和具身世界模型汇合**。WorldGen、SAGE、HunyuanWorld 等方法要求输出可遍历、可分解、可导入 game engine 或 simulator 的场景；Gen3R、World-R1、GEN3C、World-consistent Video Diffusion 则把显式 depth/XYZ/point-cloud/geometry latent 注入视频模型，试图让画面连续性变成真正的 3D/4D 一致性。PointWorld 更进一步，把机器人动作表示成全场景 3D point flow，使生成世界直接服务 MPC 和操控。〔R30–R40, R42–R52〕

最值得警惕的是：**视觉质量的提升仍明显快于几何、拓扑、物理与因果可靠性**。现有 CLIP、LPIPS、FID、多视图相似度、人类偏好评测能回答“看起来是否合理”，但不能证明网格可制造、部件可装配、角色可动画、接触动力学正确或长时世界状态不会漂移。2026 年的 P3D-Bench 与 4DWorldBench 正在补足参数化结构、物理真实性与时空一致性评测，但尚不存在一个覆盖 topology、UV、rig、PBR、physics、manufacturing 的统一标准。〔R04–R07, R24–R27, R41, R52〕

综合判断：未来 1–2 年最有研究价值的方向，不是再做一个只优化渲染图的 image-to-mesh，而是构建 **“生成—审计—修复—验证”闭环**，让生成结果在视觉、几何、结构、材质、动画、物理和许可证链路上都可验证。

## 1. 研究范围、方法与证据边界

本报告将“3D AI”划分为五个相互连接的子问题：

1. 物体级 text/image-to-3D 生成；
2. 原生 3D 表示、基础模型与 3D reconstruction foundation model；
3. 纹理、PBR、拓扑、部件、关节、rig、CAD 与 physics-ready asset；
4. 场景、城市、可遍历世界与具身仿真环境生成；
5. 动态 4D、world model、机器人和自动驾驶中的空间生成与预测。

检索优先使用 arXiv、CVF Open Access、OpenReview、论文项目主页和机构技术报告等一手来源。核心结论由 2025–2026 年文献支撑，少量 2022–2024 年论文仅用于解释技术转折。报告不将项目 demo、厂商宣传或单一 embedding score 当作独立的“已解决”证据。

证据状态分为：

- **正式发表**：CVPR/ICLR/NeurIPS 等已接收版本，可较高置信使用；
- **技术报告/预印本**：反映最新能力，但结果主要来自作者自报，需等待复现或同行评议；
- **综合推断**：由多篇论文共同指向的趋势，不等于某一篇论文的原文结论。

## 2. 技术路线的历史转折：从 SDS 到原生 3D 基础模型

### 2.1 2022–2024：借用 2D 先验，证明“生成 3D”可行

DreamFusion 用预训练 text-to-image diffusion 的 score distillation 优化 NeRF，使“无 3D 训练数据的 text-to-3D”成为可行方向。它的历史意义大于今天的工程价值：逐样本优化耗时、结果依赖相机采样与 2D prior，且容易在多个视角重复生成语义显著部位。〔R08〕

随后一批方法通过 multi-view diffusion、large reconstruction model、triplane、3D Gaussian Splatting 或 mesh extraction 缩短生成时间。这一时期的核心逻辑仍是：先在 2D 或多视图空间获得一致图像，再把它们“抬升”成 3D。该路线能够充分利用互联网级 2D 数据，但隐藏面、薄结构、真实厚度和精确拓扑通常仍属于模型的合理猜测，而非受观测约束的重建。

### 2.2 2025：feed-forward、flow matching 与 large 3D latent 成为主流

TRELLIS 的 Structured LATent（SLAT）把稀疏占用网格与多视图视觉特征结合，同一 latent 可解码到 radiance field、3D Gaussian 和 mesh；论文训练最大 2B 参数模型，并使用约 50 万个资产。这意味着研究不再绑定单一输出表示，而是把“可解码为哪些 3D 格式”纳入 latent 设计。〔R10〕

Hunyuan3D 2.0 采用几何生成与纹理生成的两阶段系统；TripoSG 强调 3D VAE、约 200 万高质量样本处理管线与 rectified flow 的共同作用；Step1X-3D 从超过 500 万资产中清洗出约 200 万高质量数据，并开放训练与适配模块。这些工作共同说明：2025 年的性能跃升不是单一网络结构带来的，而是 **数据治理、3D autoencoder、flow/DiT、multi-view texture pipeline** 的系统工程结果。〔R11–R13〕

Meta 3D AssetGen、MeshGen 与 Hunyuan3D 2.5 把 PBR 材质显式加入目标，输出或分解 albedo、roughness、metallic 等属性，使资产可重光照，而不只是把阴影烘焙进 RGB 纹理。PartGen 与 MeshArt 则分别把“可分解部件”和“关节结构”提升为生成任务：MeshArt 论文报告 structure coverage 提升 57.1%，mesh generation FID 改善 209 点。虽然不同论文的 benchmark 不可直接横向排名，这些结果仍证明结构化资产已经成为独立优化对象。〔R09, R14–R17〕

### 2.3 2026：表示本身成为竞争核心

O-Voxel 是 2026 年最清晰的方向信号之一。它不依赖 SDF/iso-surface field，而以 field-free sparse voxel 同时编码几何和 PBR 材质，支持开放、非流形和封闭内部表面。其 Sparse Compression VAE 使用 16× 空间压缩，生成模型总规模约 4B；论文在单张 H100 上报告 512³、1024³、1536³ 完整纹理资产约需 3 秒、17 秒、60 秒。这里的突破不只是分辨率，而是 **任意拓扑 + 材质 + 紧凑 latent + 可扩展生成模型** 被放在同一体系内。〔R18〕

LATTICE 的 VoxSet 介于无结构 VecSet 与规则 voxel grid 之间，以粗 voxel anchor 为 latent token 提供显式位置结构，并支持 token-level test-time scaling。AssetGen 2026 则从“极致分辨率”转向“端到端可部署”：GPU mesh simplification、cleaning、normal baking、UV unwrap、multi-view texture、backprojection 与 inpainting 被共同优化，说明工业竞争点已经从单模型精度转移到整条 asset pipeline 的时延和失败率。〔R19–R20〕

Omni123 把 text、image、3D 离散 token 放进统一自回归序列，通过 text→image→3D→image 等跨模态循环利用丰富 2D 数据约束 3D；TIGON 证明 text 与 image 条件具有互补性；SpaceControl 用训练免费的 test-time 方法把粗 primitive 或详细 mesh 作为显式几何控制；DreamCS 和 AR3D-R1 则把 3D reward、human preference 与 reinforcement learning 引入生成。这些工作指向同一趋势：**3D 模型正在从单次条件生成器，变成可控制、可编辑、可对齐、可推理的生成基础模型**。〔R21–R25〕

## 3. 表示方法：没有“唯一正确格式”，只有任务匹配

| 表示 | 优势 | 主要短板 | 更适合的目标 | 代表文献 |
|---|---|---|---|---|
| NeRF / Radiance Field | 连续体渲染、视图质量高 | 几何提取与编辑困难，渲染采样成本高 | novel-view synthesis、重建 | R08, R10 |
| 3D Gaussian Splatting | 实时渲染、显式点状 primitive、便于动态扩展 | 表面/拓扑/碰撞不天然，资产化需额外处理 | 交互浏览、4D、世界模型 | R30, R34, R39–R40, R48–R50 |
| SDF / occupancy / voxel field | 几何连续、容易提取 watertight surface | open/non-manifold/内部结构受 field 假设限制；高分辨率成本高 | 静态物体几何 | R11–R13, R18 |
| Triplane / multi-view bundle | 可复用 2D CNN/diffusion，速度和显存友好 | 依赖 decoder 与 mesh extraction，精确拓扑仍难 | 快速 image/text-to-3D | R08, R10 |
| Mesh | DCC/game/physics/CAD 的直接交换格式 | token 序列长、拓扑/UV/edge flow 难、生成失败可致下游崩溃 | 可交付资产、制造、动画 | R09, R14–R16, R20, R26 |
| Structured sparse latent / VecSet / VoxSet | 兼顾压缩、空间结构和大模型扩展 | 训练数据和预处理复杂；latent 可解释性有限 | 3D-native foundation model | R10, R18–R21 |
| 部件/程序/骨骼/场景图 token | 可编辑、可装配、可执行、适合 agent 调用 | 标注昂贵、错误会级联、开放世界结构泛化困难 | CAD、rig、scene/world generation | R15–R16, R26–R28, R32, R35, R37 |

综合推断：未来不会由单一表示统一所有 3D AI。更可能的架构是“共享生成 latent + 多解码器/多交付头”：渲染侧输出 3DGS/NeRF，资产侧输出 mesh/PBR/UV，交互侧输出 part graph/rig/physics，工程侧输出 CAD/program。TRELLIS、O-Voxel、Omni123 和 WorldGen 已分别展示了这一收敛过程的不同部分。〔R10, R18, R21, R35〕

## 4. 从漂亮模型到可交付资产

### 4.1 PBR、UV 与受控复杂度

早期方法常把光照和材质混在 RGB 纹理中，换灯光后就暴露不真实。Meta 3D AssetGen、MeshGen、Hunyuan3D 2.5、O-Voxel 逐步把 base color、metallic、roughness、opacity 等纳入表示或生成管线。AssetGen 2026 再加入受控 polygon budget、UV unwrap 和 normal baking，开始直接对 game/mobile runtime 的约束负责。〔R09, R14, R17–R20〕

尚未解决的问题包括：多视图烘焙接缝、不可见区域 inpainting、透明/半透明材质、光照—反射率分解歧义，以及材质参数是否真的能在不同 renderer 中稳定复现。

### 4.2 Topology 是视觉指标之外的核心瓶颈

“有 mesh 文件”不等于“有可用网格”。常见失败包括非流形边、自交、浮动碎片、退化三角形、孔洞、极不均匀三角形、糟糕 UV、没有适合 deformation 的 edge flow。AssetGen 2026 明确承认其 marching-cubes extraction 不保证 artist-friendly topology，角色仍可能需要 retopology。〔R20〕

因此，mesh 研究应至少报告：watertight/manifold 比率、自交和连通分量、退化面、面数/质量分布、法线连续性、UV 覆盖和重叠、简化前后 surface error。只报告 CLIP 或正面 render preference，会系统性高估资产价值。

### 4.3 部件、动画、CAD 与物理材料

PartGen 解决 fused object 不可拆分的问题；MeshArt 联合建模 articulation structure 与 part mesh；AniGen 直接生成 geometry、skeleton、skinning 的一致结构。它们共同说明，post-hoc auto-rig 对任意生成拓扑非常脆弱，原生结构生成更有长期潜力。〔R15–R16, R28〕

CADCrafter 从非受限图像生成参数化 CAD，并用 code checker 反馈提升程序/几何有效性；P3D-Bench 进一步将 executability、几何、拓扑、文本约束、多视角语义和 assembly structure 分开评测。SOPHY 则联合生成形状、纹理与影响仿真的物理材料属性。〔R07, R26–R27〕

综合推断：游戏/角色路线应优先研究 `mesh + part graph + skeleton + skinning + PBR`；工业/制造路线应优先研究 `parametric CAD + B-Rep/feature history + constraints + assembly`。两者的数据结构和成功标准不同，不应再被一个“image-to-3D”总指标混在一起。

## 5. 场景与世界生成：从“视图延展”到“可遍历结构”

### 5.1 2025：场景 latent 与布局推理

Prometheus 把 text-to-3D scene 视为 multi-view、pixel-aligned 3D Gaussian generation，并在 RGB-D latent 中分离 appearance 与 geometry；LT3SD 用 latent tree 表示粗到细的 3D scene structure，支持大范围 patch-wise diffusion 与 completion；DirectLayout 让 LLM 直接生成数值 3D layout，以 BEV→3D lifting→placement refinement 的流程提高开放词汇和空间约束能力。〔R30–R32〕

这三条路线分别解决“快速渲染场景”“大范围几何”“语义布局”，但都说明单一 end-to-end 网络很难同时满足全局布局、局部资产质量、碰撞、可达性和开放词汇。

### 5.2 2025–2026：可探索、可分解、可导入引擎

HunyuanWorld 1.0 以 panorama world proxy 和 semantically layered mesh 生成可 360° 探索、可导出 mesh、可分解对象的世界。WonderZoom 引入可动态增长的 scale-adaptive Gaussian surfels，使用户从宏观场景逐层“缩放”并生成此前不存在的微观内容。〔R33–R34〕

WorldGen 是 production-oriented world generation 的代表：LLM 驱动 procedural generator 先确定 terrain、blockout 和 navmesh，再由图像/3D generator 添加风格与细节，最后把整体重建分解为独立 mesh 并增强。它的关键不是“更像一张照片”，而是显式保证 traversability、对象分解与 game-engine compatibility。〔R35〕

Gen3R 把 VGGT 的几何 token 与 video diffusion appearance latent 对齐，联合生成 RGB video、camera、depth 和 global point cloud，显示 reconstruction foundation model 与 generative model 正在互相强化。SAGE 则以 agent 调度 layout/object generator 和 semantic、visual、physical critic，迭代生成 simulator-ready 环境；D3D-GEN 是截至检索日较新的预印本之一，进一步把 domain RAG、floorplan、object placement 与 Isaac Sim/Gazebo 输出连接起来。〔R36–R38〕

综合推断：大型场景的主流架构很可能是 **agent + procedural/constraint solver + 2D/video prior + 3D asset generator + physics validator**，而不是把所有问题压进一个 diffusion model。WorldGen 和 SAGE 已经给出这一组合式路线的清晰证据。〔R35, R37〕

## 6. 4D、几何基础模型与 Physical AI

### 6.1 4D 表示从“动态渲染”转向“闭环状态”

PerpetualWonder 建立 physical state 与 visual primitive 的双向链接，使生成式 refinement 能回写物理状态；WorldReel 同时生成 RGB、pointmap、camera trajectory 和 dense flow，以单一显式 4D scene 约束不同视角与非刚体运动。4DWorldBench 则把 perceptual quality、condition–4D alignment、physical realism、4D consistency 放入统一框架。〔R39–R41〕

这标志着 4D 研究的评价目标从“某个动态序列看起来连续”转向“同一个世界状态能否跨相机、时间和交互持久存在”。

### 6.2 Feed-forward geometry foundation model 成为世界生成底座

VGGT 能从一张到数百张图像在一次前馈中估计 camera、point map、depth 和 3D tracks；D4RT 把 dynamic depth、correspondence、camera 与 tracking 统一进单一 Transformer；VGGT-Ω 把这一范式扩展到 10B 规模，并展示 geometry token 对机器人策略的增益。〔R29, R42–R43〕

版本风险提示：VGGT-Ω [官方项目页](https://vggt-omega.github.io/) 于 2026-08-18 提示，已发布的 1B 模型所继承 checkpoint 可能存在 benchmark contamination，Table 1/2 中部分 1B 指标可能偏高。本报告没有依赖这些具体指标，但后续复现和横向比较应使用作者修正后的 checkpoint/结果，并保留数据污染审计。

这些模型的作用不仅是“重建器”。它们可作为生成模型的几何编码器、3D reward、数据清洗器、相机估计器和闭环一致性检查器。Gen3R 与 World-R1 已分别展示 geometry foundation model 和 3D reward 如何约束生成。〔R36, R44〕

### 6.3 视频 world model 正在显式加入 3D 约束

Endless World 用 attention sink 和 VGGT 3D features 支持长视频；Voyager 联合生成 RGB-depth video，并维护 world cache；GEN3C 与 World-consistent Video Diffusion 使用 point-cloud cache 或 global XYZ，使 camera-controlled video 不再只靠 2D optical consistency。4D-LRM 和 DGS-LRM 则以 feed-forward 4D Gaussian/scene flow 重建连接 video 和 dynamic 3D。〔R45, R47–R51〕

World-R1 的 reinforcement learning 结果进一步表明，3D foundation model/VLM reward 可以在不改基础视频模型结构的情况下提高 3DGS 重渲染一致性；但其结果仍需独立复现，且 3D consistency metric 不等于物理因果正确。〔R44〕

### 6.4 具身世界模型的真正门槛是 action 与 physics

PointWorld 不直接预测某一机器人关节动作，而把动作表述为全场景 3D point flow；作者使用约 200 万 trajectories、500 小时 Franka/双臂人形数据，并把预测接入 MPC。这个设计比“生成下一帧视频”更接近可迁移的操控世界模型，因为状态和动作共享 3D 空间。〔R46〕

NVIDIA Cosmos 提供数据清洗、video tokenizer、diffusion/autoregressive WFM 和后训练工具链，并从约 2000 万小时视频中抽取约 1 亿 clips。技术报告同时明确承认：当前模型仍缺乏可靠 object permanence，在 contact-rich dynamics、instruction following、gravity/light/fluid 等物理规律上会失败，逼真视频不等于可靠 simulator。〔R52〕

因此，世界模型的研究验收应包含：动作条件可控性、对象永久性、接触与碰撞、尺度/相机准确性、长时状态漂移、策略闭环收益，而不能只用 VBench/FID/视频人类偏好。

## 7. 数据与评测：当前进展最容易被高估的地方

### 7.1 数据规模与数据质量的张力

Objaverse-XL 提供超过一千万去重 3D 对象，推动大规模训练，但互联网资产的几何、材质、方向、许可和重复问题需要额外治理。Step1X-3D 与 TripoSG 均把清洗管线作为核心贡献，说明“更多资产”只有在去重、语义过滤、几何修复和标准化后才真正形成训练价值。〔R03, R12–R13〕

HY3D-Bench 发布约 252k watertight mesh/多视图资产、240k 结构部件分解和 125k AIGC 长尾资产；作者用较小模型得到接近更大基线的 embedding 分数，直接支持“高质量清洗与结构标注可以抵消部分模型规模差距”的判断。〔R06〕

### 7.2 评测必须分层

建议将 3D 生成评测固定为四层，而不是汇总成单一排行榜：

1. **感知与条件层**：CLIP/ULIP/Uni3D、LPIPS、FID/KID、多视图一致性、blind human preference；
2. **几何层**：Chamfer、F-score、IoU、normal/depth error、薄结构、隐藏面、尺度和相机误差；
3. **工程资产层**：watertight/manifold、自交、组件、面质量、UV、PBR、LOD、rig、skin、CAD program executability；
4. **场景/物理层**：碰撞、稳定性、可达性、navmesh、接触、对象永久性、时空一致性、task success。

T3Bench 揭示复杂组合、多物体与环境描述更难；3DGen-Bench 用公众/专家偏好训练自动 evaluator；P3D-Bench 把 parametric execution、topology 与 assembly 独立出来；4DWorldBench 扩展到物理与 4D consistency。这些基准互补，但仍未形成统一标准。〔R04–R07, R41〕

### 7.3 常见失败模式

- **单图背面幻觉**：罕见类别、非对称对象、机械内部与遮挡区域尤其不可靠。〔R20〕
- **Janus 与多视图语义重复**：2D prior 可能在不同相机重复生成显著语义部位。〔R08, R24〕
- **纹理接缝和材质漂移**：multi-view synthesis、UV baking 与不可见区 inpainting 之间存在结构性冲突。〔R09, R14, R17–R20〕
- **语义正确、装配错误**：对象数、部件连接、相对位置、功能 affordance 和精确参数容易失败。〔R04, R07, R15–R16, R26〕
- **静态漂亮、动态失效**：拓扑不适合 deformation、skin weight 不稳定、碰撞/质量/摩擦缺失。〔R20, R27–R28〕
- **视频逼真、物理错误**：object permanence、contact-rich dynamics、gravity、fluid 与 instruction following 仍是公开短板。〔R41, R52〕
- **跨论文指标不可比**：训练数据、硬件、renderer、prompt、相机、闭源基线和人类测试协议不同，不能用单一数字给所有系统排总榜。

## 8. 研究方向优先级与可执行建议

### 8.1 第一优先：生成—审计—修复闭环

最具差异化、也最贴近真实需求的课题是：给任意 3D generator 增加一个资产审计器和修复器。审计器同时检查 manifold、自交、孔洞、部件、UV、PBR、rig、碰撞和物理；修复器以程序反馈、3D reward 或可微损失迭代修改。DreamCS、AR3D-R1、CADCrafter、SAGE 已分别证明 3D reward、RL、code checker 与 critic loop 的可行性，但尚未有统一工程闭环。〔R23–R27, R37〕

建议的最小论文原型：

- 选一个开放 image-to-3D backbone；
- 建立 6–10 个可自动验证的 asset checks；
- 用 failure-aware preference/reward 或程序化修复；
- 同时报告视觉、人类、几何、工程四层指标；
- 发布失败资产和修复前后 mesh，而不只发布渲染视频。

### 8.2 第二优先：结构化、可编辑、可动画资产

研究 shared latent 联合预测 `geometry + part graph + skeleton + skinning + PBR`，但先限定到窄类别或模板拓扑，以降低标签噪声。PartGen、MeshArt、AniGen 可作为三种互补起点。〔R15–R16, R28〕

### 8.3 第三优先：可仿真的场景/世界生成

把 scene generation 定义成 task-conditioned environment compilation：输入任务和领域约束，输出 layout、独立资产、navmesh、collision、physics、lighting 与 simulator package。WorldGen、SAGE、D3D-GEN 已提供可组合架构；真正的研究空间在自动验证与 task success，而非继续堆叠视觉 prompt。〔R35, R37–R38〕

### 8.4 第四优先：显式 3D/4D world model

以 VGGT/D4RT 类几何模型为 memory，把 video WFM 作为未观测区域和外观的 generative prior，并用 action/point-flow 闭环更新世界状态。PointWorld、Gen3R、PerpetualWonder、World-R1 分别覆盖 action、geometry-generation coupling、physical-visual state link 和 reward alignment。〔R36, R39, R42–R46〕

### 8.5 不建议的短期路线

- 仅用 CLIP/FID 改进一个 image-to-mesh baseline，却不测拓扑和工程可用性；
- 将生成视频的视觉连续性直接称为“学会物理”；
- 在来源/许可不清的大规模 3D 资产上训练，却不保存 provenance、license、hash 和派生链；
- 用不同论文的作者自报数字做简单总榜，而忽略数据与协议差异。

## 9. 方向选择矩阵

| 方向 | 新颖性空间 | 数据门槛 | 算力门槛 | 工程价值 | 主要风险 |
|---|---:|---:|---:|---:|---|
| 通用 image/text-to-3D backbone | 中低 | 高 | 很高 | 高 | 头部团队数据与算力优势明显 |
| Topology/UV/PBR 审计与修复 | 高 | 中 | 中 | 很高 | 需建立可靠自动指标 |
| Part/rig/animation-ready generation | 高 | 高 | 高 | 很高 | rig/skin 标注稀缺、拓扑耦合强 |
| Parametric CAD/assembly | 高 | 中高 | 中 | 很高 | 精确几何与程序正确性要求高 |
| Simulator-ready scene generation | 高 | 高 | 高 | 很高 | 资产、布局、物理错误会级联 |
| 4D reconstruction foundation model | 中高 | 很高 | 很高 | 高 | 时空标注与训练成本极高 |
| Action-conditioned 3D world model | 很高 | 很高 | 很高 | 很高 | 闭环评测、真实机器人数据昂贵 |

若以个人或小团队可执行性为约束，本报告推荐顺序为：

1. topology/UV/PBR 审计与修复；
2. 面向窄领域的 CAD/rig/physics-ready generation；
3. 基于开放模型的 simulator-ready scene compiler；
4. 最后才是训练新的通用 3D foundation model。

## 12. 研究局限与更新建议

1. 2026 年 4–8 月仍有大量论文只以 arXiv 或技术报告形式公开；本报告已在正文和参考文献中标注，不能把预印本等同于同行评议结论。
2. 不同论文的硬件、renderer、prompt、数据和 closed-source baseline 不统一，文中的速度与质量数字仅用于理解各自系统，不用于构造跨论文总排名。
3. 本报告没有对 52 篇论文逐一复现实验；结论依据论文全文、官方摘要、项目页和跨来源一致性。最关键的 O-Voxel、AssetGen 2026、WorldGen、4DWorldBench、Cosmos 已额外核对正文与 limitations/conclusion。
4. 3D AI 更新速度很快。建议每季度追加检索，并重点跟踪：开放训练数据/许可、拓扑与资产审计、rig/physics、world model 长时一致性、agentic scene compilation、可复现 benchmark。

## 13. 方法记录

研究共拆分为三条并行问题线：

- 资产生成与表示；
